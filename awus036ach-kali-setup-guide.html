HOME LAB SETUP

AWUS036ACH + Kali Linux

Getting your adapter installed, recognized, and verified in monitor mode — the part that actually trips people up with this card.

What this guide covers

  • Choosing how to run Kali (VM vs. bare metal vs. live USB) for this adapter
  • Installing VMware Workstation on Windows and creating the Kali VM
  • Installing Kali Linux
  • Installing the correct RTL8812AU driver (the stock kernel one is unreliable for this card)
  • Verifying monitor mode and packet injection actually work
This does not cover capturing a handshake or cracking a password. That workflow changes syntax across tool versions, so you're better served by the maintained official documentation — linked at the bottom once your adapter is confirmed working.

STEP 1 Pick how you'll run Kali

This decision affects whether the adapter works at all, so make it first.

USB adapters and virtual machines don't mix well by default. A VM only sees USB devices if its hypervisor passes them through, and passthrough can introduce enough latency or packet handling overhead to make injection flaky or fail outright. Bare metal or a live USB gives the adapter direct access to the kernel driver.

Your three options:

  • Bare metal install — most reliable for monitor mode/injection. Needs a spare laptop or dedicated partition.
  • Live USB (persistent) — boot Kali from a USB stick without touching your main OS. Good middle ground, slight performance cost on every boot.
  • Virtual machine (VirtualBox/VMware) with USB passthrough — most convenient, least reliable for this specific use case. Workable for learning the OS and tools, but expect possible injection issues.

If your goal is a working audit setup rather than just poking around Kali, use bare metal or a persistent live USB.

STEP 1B Install VMware Workstation on Windows

Since you're on Windows and going the VM route — here's that setup, plus the USB passthrough config the adapter needs.

Download and install VMware Workstation Pro

Broadcom made Workstation Pro free for personal use. Get it from the official page: vmware.com/products/desktop-hypervisor/workstation-and-fusion (look for "Workstation Pro" under the Windows downloads, sign up for a free Broadcom account if prompted).

Run the installer, accept defaults, and reboot if it asks to. If you have Hyper-V, WSL2, or "Memory Integrity / Core Isolation" enabled in Windows, VMware may warn about conflicts — those features compete with VMware's own hypervisor. Easiest fix: disable Hyper-V and Core Isolation for this use case:

REM Run in an elevated Command Prompt
dism.exe /Online /Disable-Feature:Microsoft-Hyper-V /All
bcdedit /set hypervisorlaunchtype off

Then reboot. (Windows Security → Device Security → Core Isolation → turn off Memory Integrity, also reboot.)

Create the Kali VM

  • Open VMware Workstation → "Create a New Virtual Machine" → Typical
  • Point it at the Kali ISO you'll download in Step 2 (VMware can auto-detect it, but choose "I will install the operating system later" if it misdetects the Linux version — select "Debian 12.x 64-bit" manually, since Kali is Debian-based)
  • Allocate at least 60GB disk, 4GB+ RAM, 2+ CPU cores
  • Finish, then edit VM settings before first boot: remove the default USB controller version mismatch issues by setting USB Compatibility to USB 3.1 under VM Settings → USB Controller — this matters because the AWUS036ACH is a USB 3.0 device and will misbehave under USB 2.0 emulation
Install VMware Tools inside Kali after the OS install (Step 2) — sudo apt install -y open-vm-tools open-vm-tools-desktop — this improves USB handling, clipboard sharing, and display scaling.

Pass the adapter through to the VM

Plug the AWUS036ACH into a USB 3.0 port on the Windows host. With the Kali VM running, go to VMware's VM menu → Removable Devices → look for the Realtek/RTL8812AU entry → Connect (Disconnect from Host). This hands the raw USB device to the VM; Windows will no longer see it until you disconnect it back.

Inside Kali, confirm it arrived:

lsusb

If it doesn't show up, check VM Settings → USB Controller is set to USB 3.1 (not 2.0), and that Windows' own WiFi driver for the adapter isn't holding onto it — unplug and replug after connecting it to the VM if needed.

Reminder from earlier: USB passthrough on a VM is the least reliable path for monitor mode and injection specifically. If Step 4's injection test fails consistently and you've ruled out the driver, that's usually the passthrough layer adding overhead the real hardware wouldn't have — bare metal or a live USB are the fallback if this becomes a wall.

STEP 2 Install Kali Linux

Download

Get the image from the official source only: kali.org/get-kali. Since you're installing into a VMware VM, grab the "Installer" ISO (not the pre-built VM image — building it yourself in Step 1B gives you control over the USB controller setting that matters for this adapter).

  • "Installer" image for bare metal
  • "Live" image for a USB stick
  • "Virtual Machines" pre-built image for VirtualBox/VMware (saves you the install step, but see the passthrough caveat above)

Verify the download (don't skip this)

Kali images are a common target for tampered downloads. Check the SHA256 sum against the value published on the Kali site:

sha256sum kali-linux-2026.X-installer-amd64.iso

Write it to USB

Use balenaEtcher (Windows/Mac/Linux) or dd on Linux/Mac:

sudo dd if=kali-linux-2026.X-installer-amd64.iso of=/dev/sdX bs=4M status=progress conv=fsync
Double-check /dev/sdX with lsblk first — the wrong device here wipes it.

Install

Boot from the USB, choose "Graphical Install," and follow the prompts (disk partitioning, user account, etc.). Defaults are fine for a learning setup. Once it reboots into Kali, update everything before touching drivers:

sudo apt update && sudo apt full-upgrade -y
sudo reboot

STEP 3 Install the RTL8812AU driver

This is the step that actually causes most people's "my adapter won't go into monitor mode" problems.

Plug in the AWUS036ACH and check if Linux sees it at all:

lsusb

You should see a line mentioning Realtek or RTL8812AU. If nothing shows up, try a different USB port (preferably USB 3.0, plugged directly in — not through a hub).

Why you need a separate driver

Kali's kernel sometimes includes a partial in-tree driver for this chipset that can handle basic WiFi but doesn't support monitor mode or injection properly. The driver maintained by the aircrack-ng project fixes this.

Install build dependencies

sudo apt update
sudo apt install -y build-essential dkms git libelf-dev linux-headers-$(uname -r)

Clone and install the driver

git clone https://github.com/aircrack-ng/rtl8812au.git
cd rtl8812au
sudo make dkms_install

This builds the driver via DKMS, which means it automatically rebuilds itself after future kernel updates — important, because this is the single most common reason the driver "stops working" a few weeks later.

Reboot and recheck

sudo reboot

After reboot, confirm the interface shows up:

iwconfig

You should see an interface like wlan0 or wlan1 listed alongside your other network interfaces.

If the driver build fails: it's almost always a kernel header mismatch. Run uname -r and confirm linux-headers-$(uname -r) actually installed a matching version — check with dpkg -l | grep linux-headers. A fresh apt full-upgrade followed by a reboot before reinstalling the driver fixes most of these cases.

STEP 4 Verify monitor mode and injection

Confirm the setup actually works before you rely on it for anything.

Check for interfering processes

sudo airmon-ng check

If it lists processes like NetworkManager or wpa_supplicant that could interfere, kill them:

sudo airmon-ng check kill

Enable monitor mode

sudo airmon-ng start wlan0

(Replace wlan0 with whatever iwconfig showed for your adapter.) This typically creates a new interface, often named wlan0mon. Confirm it:

iwconfig

You should see Mode:Monitor on the new interface.

Confirm you can see traffic

sudo airodump-ng wlan0mon

If this lists nearby networks (yours and visible neighbors, which is normal and passive — you're just listening, not connecting), monitor mode is working. Press Ctrl+C to stop.

Test packet injection

sudo aireplay-ng --test wlan0mon

A healthy result reports injection working with a reasonable success percentage against nearby access points. If it reports 0% or fails outright against every AP, the driver or adapter isn't injecting properly — revisit Step 3 before going further.

  • Adapter shows up in lsusb
  • Interface appears in iwconfig
  • Monitor mode interface created successfully
  • airodump-ng shows nearby networks
  • aireplay-ng --test reports successful injection

If all five check out, your hardware and driver setup is solid.

From here: auditing your own network's password strength

With monitor mode and injection confirmed working, the next stage — capturing a WPA/WPA2 handshake from your own router and testing it against a wordlist — is a well-documented, versioned workflow that changes syntax across tool updates. Rather than a static write-up here, use the actively maintained official reference:

aircrack-ng.org/documentation.html

A few things worth knowing going in:

  1. Only run this against networks you own or have explicit written permission to test.
  2. If your router supports WPA3, this handshake-capture method largely doesn't apply — WPA3's SAE handshake resists this style of offline attack.
  3. If WPS is enabled on your router, that's often a separate and more significant weak point than the password itself — worth checking and disabling regardless.
  4. A password that survives a decent wordlist for more than a few hours on consumer hardware is doing its job. If yours falls in minutes, that's your actionable takeaway: switch to a longer, random passphrase (12+ characters).
Reference only — driver repos and tool syntax change over time; check the linked official sources if anything here looks out of date.
